# GPT-5.1 深度研究框架零基础超长教程

> 本教程专门为没有技术背景的用户准备，手把手教你如何使用本仓库提供的研究框架，通过柏拉图AI等 API 中转站调用 GPT-5.1，完成涉及投资研究等复杂主题的上万字报告。内容包含：环境准备、安装运行、配置讲解、实战示例、常见问题与故障排查、扩展玩法、效率与安全建议等。请按需跳读；每个步骤都尽量写得详尽易懂。

## 1. 为什么要用这个框架？
- **一站式自动化**：从搜集资料、摘要整理到生成完整报告，全部流程自动串联，减少人工操作。
- **可控的深度与预算**：你可以自由设置搜索数量、迭代轮次、输出长度、模型温度等，适配“深度研究”场景。
- **模块化可替换**：搜索、抓取、模型接口都可替换，既能直连柏拉图AI，也可在离线模式做演示或测试。
- **长文产出友好**：专门为万字级报告设计，可分层规划提纲、分段撰写并合并，减少思路散乱。

## 2. 你需要准备什么？
1. **一台电脑**：Windows、macOS、Linux 均可，至少 4GB 内存、10GB 空间更稳妥。
2. **Python 环境**：建议安装 Python 3.9 及以上版本。
3. **网络与 API Key**：
   - 如果要真实调用 GPT-5.1，请准备好柏拉图AI或兼容 OpenAI 接口的密钥，并确认网络可访问。
   - 如果暂时没有密钥，可先用框架自带的离线演示组件（不会调用网络）。
4. **命令行工具**：Windows 可使用 PowerShell，macOS/Linux 使用自带终端。

## 3. 第一次使用：从零开始安装
### 3.1 获取代码
- 在终端执行：
  ```bash
  git clone https://github.com/your-username/GPT-5.1-deep-research.git
  cd GPT-5.1-deep-research
  ```
- 如果不会用 git，也可以在 GitHub 网页点击 “Code” → “Download ZIP”，下载后解压，再在终端进入解压目录。

### 3.2 安装依赖
```bash
pip install -r requirements.txt
```
> 安装过程中出现 `Permission denied` 可在命令前加 `sudo`（macOS/Linux），或在 Windows 以管理员身份运行 PowerShell。若提示找不到 `pip`，可尝试 `python -m pip install -r requirements.txt`。

### 3.3 配置环境变量（用于真实调用 GPT-5.1）
- 根据你的中转或直连方式，设置以下变量（示例：bash）：
  ```bash
  export OPENAI_API_KEY="你的密钥"
  export OPENAI_BASE_URL="https://你的中转域名/v1"  # 若使用柏拉图AI，请填写其提供的地址
  ```
- Windows PowerShell 示例：
  ```powershell
  setx OPENAI_API_KEY "你的密钥"
  setx OPENAI_BASE_URL "https://你的中转域名/v1"
  ```
- 如果只想先离线体验，不需要设置这些变量。

## 5. 认识框架的“乐高”部件（非技术版）
- **ResearchConfig**：集中管理“预算”和“风格”设置，比如：
  - `model`：使用的模型（如 gpt-5.1）。
  - `search_results`：每轮搜索抓取多少条结果，数字越大覆盖越广。
  - `max_search_rounds`：搜索轮次，越多越深入。
  - `report_word_target`：目标字数，适合设为 8000–15000。
  - `temperature`：创造性，0 更稳健保守，1 更发散。
- **OpenAIClient / EchoLLM**：
  - 前者用于真实调用 GPT-5.1。
  - 后者为离线演示，返回可预测的文本，便于测试。
- **DuckDuckGoSearch / StaticSearchProvider**：
  - 前者联网搜索。
  - 后者用预设数据，离线可用。
- **RequestsFetcher / StaticFetcher**：
  - 前者联网抓取网页正文。
  - 后者提供静态文本，便于离线演示。
- **ResearchOrchestrator**：总指挥，按顺序调度“搜索→抓取→摘要→写作”。
- **Summarizer / Planner**：分别负责“总结每个来源”和“生成提纲与最终报告”。

理解成“选好积木→交给总指挥→输出报告”。

## 6. 实战：跑一份投资研究报告
以下示例演示“AI 基础设施的长期前景”研究。你可以根据需要替换主题。

### 6.1 配置建议
```python
from deep_research import (
    DuckDuckGoSearch,
    OpenAIClient,
    ResearchConfig,
    ResearchOrchestrator,
    RequestsFetcher,
)

config = ResearchConfig(
    model="gpt-5.1",           # 使用 GPT-5.1
    search_results=12,         # 每轮抓取 12 条结果
    max_search_rounds=3,       # 搜索 3 轮，覆盖度更高
    report_word_target=12000,  # 目标 1.2 万字
    temperature=0.4,           # 适度探索
)

llm = OpenAIClient(model=config.model)
search = DuckDuckGoSearch()
fetcher = RequestsFetcher()
orchestrator = ResearchOrchestrator(
    llm=llm, search=search, fetcher=fetcher, config=config
)

artifacts = orchestrator.run("投资研究：AI 基础设施的长期前景")
print(artifacts.report)
```

### 6.2 如何保证“万字级”输出？
- 将 `report_word_target` 调高（如 15000–20000）。
- 调整 `max_search_rounds` ≥ 3、`search_results` ≥ 10，让资料更丰富。
- 如果内容偏短，可在报告生成后重新触发“补全”步骤：
  - 手动修改脚本，追加一次 `orchestrator.llm.complete(...)` 请求，让模型“扩写每节内容”。

### 6.3 控制引用与可信度
- 在 `ResearchConfig` 中可添加自定义提示，如要求“标注来源”、“对冲偏见”。
- 若要强制引用原文链接，可在生成报告后，用简单规则为每个摘要附上链接再交给 LLM 合并。

### 6.4 输出格式与保存
- 推荐保存为 Markdown：便于导出 PDF 或导入笔记软件。
- 如需 Word，可将生成的 Markdown 粘贴到 Word，再用“样式”调整目录和标题。

## 7. 不联网/无密钥也能试：离线演示模式
### 7.1 为什么需要离线模式？
- 测试脚本是否能跑通；
- 演示流程给团队看，避免真实消耗额度。

### 7.2 离线示例代码
```python
from deep_research import (
    EchoLLM,
    ResearchConfig,
    ResearchOrchestrator,
    StaticFetcher,
    StaticSearchProvider,
)

config = ResearchConfig(report_word_target=500)
llm = EchoLLM()

fetcher = StaticFetcher()

orchestrator = ResearchOrchestrator(llm=llm, search=search, fetcher=fetcher, config=config)
artifacts = orchestrator.run("示例主题：新能源发展前景")
print(artifacts.report)
```
> 该模式不会联网，输出是可预测的“占位文本”，但能验证流程与接口。

## 8. 自定义与进阶玩法
### 8.1 换用自己的搜索引擎
- 你可以参考 `deep_research/search.py`，实现一个新的类继承 `SearchProvider`，只要满足 `search(query: str) -> list[str]` 的接口即可。
- 例如接入企业内网搜索、学术搜索 API，将其传给 `ResearchOrchestrator` 即可。

### 8.2 增强提纲与章节控制
- 在 `planner.py` 中，提纲的提示词可以加入更多“章节模板”。你可以复制现有提示，添加特定行业的标准框架（如 SWOT、波特五力、DCF 模型步骤）。
- 报告不够“有条理”时，试着在 prompt 中要求“先列清晰目录，再逐节生成内容，并在结尾回顾风险与展望”。

### 8.3 分段写作 + 最终合并
- 对于 2 万字以上报告，可按章节分批调用 LLM：
  1. 让 `planner` 先只生成目录；
  2. 遍历目录每个章节，用 `llm.complete` 单独生成长段落；
  3. 最后把所有章节组合并，用 `Summarizer` 或再调用一次 LLM 做整体润色。
- 这种方式能降低单次调用的 token 压力，减少报错。

### 8.4 提高引用可信度的技巧
- 在抓取时保留页面标题与链接，并在摘要里嵌入：`[来源名称](链接)`。
- 让模型在写作 prompt 里强制“每个关键论点必须给出来源编号”。
- 对关键数据（市场规模、增长率）可要求模型输出“原文摘录 + 解释”，便于人工复核。

### 8.5 节省成本与时间
- 减少 `search_results` 和 `max_search_rounds` 以缩小范围。
- 调低 `report_word_target` 先出短版，确认方向后再跑长版。
- 使用 `EchoLLM` 先验证流程，再切换 `OpenAIClient` 正式生成。

## 9. 常见问题 (FAQ)
1. **运行时报 `ModuleNotFoundError`？**
   - 确认已在项目根目录运行，且执行过 `pip install -r requirements.txt`。
2. **提示找不到 API Key？**
   - 检查环境变量是否正确设置；终端重启后再试。
3. **网络被墙/搜索失败？**
   - 可先用离线模式验证流程；或切换代理/镜像源。
4. **输出太短或不连贯？**
   - 调高 `report_word_target`，并增加搜索轮次；在提示里要求“结构化写作”。
5. **重复内容多？**
   - 在 prompt 中增加“去重”“合并同类项”；或把摘要阶段的输出传入模型让它“先去重后写作”。
6. **如何得到可复制的引用标记？**
   - 在写作提示里要求使用 `[来源名]` 或脚注形式；或在生成后自行用正则替换。

## 10. 故障排查清单
- **确认依赖**：`pip list | grep -E "requests|beautifulsoup4|duckduckgo-search"` 是否存在。
- **检查网络**：浏览器访问你设置的 `OPENAI_BASE_URL` 是否可通。
- **尝试最小脚本**：使用 `EchoLLM + StaticSearchProvider + StaticFetcher` 确认流程无误。
- **日志打印**：在 `orchestrator.run` 前后插入 `print` 查看搜索词、摘要长度，快速定位卡点。
- **重试策略**：对于偶发的网络错误，可以在 `RequestsFetcher` 里增加简单重试（如 `requests` 的 `Session` + `Retry`）。

## 11. 安全与合规提示
- 尊重爬取网站的 **robots 协议** 和版权要求，勿大规模抓取受限内容。
- 对涉及金融投资的结论，请务必 **人工复核**，模型输出不构成投资建议。
- 不要在提示中输入敏感个人信息；如需处理内部资料，建议在离线或内网环境运行。

## 13. 进阶：打造你自己的“研究助手”脚本
下面是一份更完整的脚本范例，展示如何：
- 根据主题自动生成多条搜索词；
- 将中间摘要保存到本地；
- 在报告末尾附上“下一步研究建议”。

```python
from deep_research import (
    DuckDuckGoSearch,
    OpenAIClient,
    ResearchConfig,
    ResearchOrchestrator,
    RequestsFetcher,
)

config = ResearchConfig(
    model="gpt-5.1",
    search_results=15,
    max_search_rounds=4,
    report_word_target=15000,
    temperature=0.35,
)

llm = OpenAIClient(model=config.model)
search = DuckDuckGoSearch()
fetcher = RequestsFetcher()
orchestrator = ResearchOrchestrator(
    llm=llm, search=search, fetcher=fetcher, config=config
)

# 运行研究
artifacts = orchestrator.run("投资研究：AI 基础设施的长期前景")

# 保存中间摘要
with open("sources_summary.md", "w", encoding="utf-8") as f:
    for item in artifacts.summaries:
        f.write(f"## 来源: {item.source}\n\n{item.summary}\n\n")

# 在报告后追加“下一步计划”
extended_report = artifacts.report + "\n\n## 下一步研究建议\n- 访谈 3 家云厂商的采购负责人\n- 对比 GPU、ASIC、NPU 未来 3 年的供需预测\n- 跟踪 AIGC 行业的成本结构演变"

with open("final_report.md", "w", encoding="utf-8") as f:
    f.write(extended_report)
```

## 14. 如何进一步“加大力度”
- **提高搜索广度**：`search_results` 设置为 20 以上，并增加 `max_search_rounds`，能覆盖更多信息源。
- **多语言混合搜索**：在主题里加入英文关键词，或在搜索阶段添加“EN”/“中文”两套关键词。
- **多模型协作**：
  - 先用成本较低的模型（如 `gpt-4.1-mini`）跑草稿；
  - 再用高阶模型（`gpt-5.1`）做润色与事实校对。
- **结构化引用**：让模型输出 JSON 结构，包含论点、证据、来源 URL，再由脚本合成 Markdown。

- **知识库沉淀**：把 `sources_summary.md` 和最终报告存入企业知识库（如语雀、Notion），后续可再次检索或复用。
